# Manual de governança de acessos

## Objetivo

Este manual orienta a concessão, a revisão e a revogação de acesso ao Keller Hub. Ele deve ser utilizado em conjunto com o manual específico de cada perfil.

## Modelo de autorização

A permissão efetiva combina:

1. **Perfil**, que define as ações permitidas.
2. **Escopo de área**, que define os dados alcançados.
3. **Visibilidade do item**, que pode ser pública na área, compartilhada ou privada.
4. **Convite individual**, usado para exceções com nível explícito.

## Perfis disponíveis

| Perfil | Finalidade | Escopo padrão |
| --- | --- | --- |
| Técnico | Execução operacional | Suas áreas e itens atribuídos |
| Gestor | Gestão tática da carteira | Áreas das quais é membro |
| Alta Administração | Supervisão estratégica | Todas as áreas |
| Administrador/PMO | Governança da solução | Todas as áreas e configurações |

## Níveis de permissão individual

- **Editar tudo:** conteúdo, estrutura e configuração do item.
- **Editar conteúdo:** informações do trabalho, sem alterar estrutura ou configuração.
- **Editar só itens atribuídos a mim:** atualização limitada às responsabilidades da pessoa.
- **Somente leitura:** consulta sem alteração.

## Procedimento de concessão

1. Confirmar a necessidade funcional e o perfil solicitado.
2. Identificar as áreas necessárias para o trabalho.
3. Vincular a pessoa como Membro ou Dono da área.
4. Usar convite individual somente para uma exceção documentada.
5. Aplicar o menor nível de permissão suficiente.
6. Simular o perfil e o filtro de área para validar o resultado.
7. Conferir o registro correspondente na trilha de auditoria.

## Revisão periódica

Revise acessos quando houver mudança de lotação, função, responsabilidade ou encerramento de vínculo. A revisão deve incluir áreas, convites individuais, itens privados e permissões de edição completa.

## Revogação

1. Remover a pessoa das áreas que não sejam mais necessárias.
2. Remover convites individuais.
3. Transferir responsabilidades pendentes.
4. Verificar a trilha de auditoria.
5. Confirmar por simulação que os dados deixaram de aparecer.

## Proteção de dados

O acesso deve observar finalidade, necessidade e menor privilégio. Informações orçamentárias ficam ocultas para o perfil Técnico. Conteúdo de áreas restritas, itens privados e relatórios autenticados não deve ser redistribuído fora dos canais autorizados.
